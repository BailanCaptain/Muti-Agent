# F037 内容质量加固收敛（B027 / B028）

**日期：** 2026-07-13

**参与：** 小孙、范德彪；独立架构审计 agent 只读补充

**结论：** 方向已由小孙拍板，按 Bug 流程进入 TDD；不重新设计日报。

## 1. 收敛后的产品目标

1. 社区动态只刊登 AI 相关的研究、实质讨论和进展；抱怨、求助、人生建议、八卦和空泛热议不进入正式日报。
2. “推理”只表示大模型推理/部署/服务相关研究、工程进展和讨论。GPU 融资、公司投资等商业新闻不能借“GPU”归入推理。
3. 推理是 AI 板块的重点，不是 AI 板块的全部。原有子栏继续保留；确实无合格推理时允许为空，不拿低质内容填充。
4. 开源榜单保持一个总榜名和四个原有分组。先判断是否以 AI 为核心，再按真实增星排序；AI 相关性不再充当排序倍率。
5. 周榜/月榜不做跨日去重；增长榜/新秀榜记录 NEW、连续上榜和重新上榜状态。

## 2. 架构共识

### B027：发布清单是唯一真相源

抓取池是证据，不等于可发布内容。分类/编辑阶段产生显式批准的发布条目；邮件、网页 curated 视图和 shown ledger 都只消费这份批准集合。renderer 不再从 raw pool 自行补“其余速览”，podcast/YouTube 等直出路径也必须进入同一批准边界。

推理候选从完整新鲜 AI 池中先做高召回保护，再与常规候选一起交给语义审核，避免在 `MAX ai` 截断前消失。分类维度拆成内容类型与展示标签；同一条只展示一次，优先级为“推理 → 公司 → 国产 → 开源 → 研究 → 其他”。

### B028：准入与排序彻底分离

GitHub topics/description/README 只用于 `yes / no / unknown` 准入判断；只有 `yes` 发布，`unknown` 失败关闭并记录原因。排名只看对应窗口的真实新增 star，解析失败不伪造 0。

榜间同仓去重与跨日状态分开：同一期仍按现有分组顺序只显示一次；跨日抑制只适用于增长榜/新秀榜的状态计算，周榜/月榜每天展示当前排名。

## 3. 明确不做

- 不改邮件整体格局、原有文案、栏目名或现有开源榜单排版。
- 不实施此前讨论的“两行容纳方案”。
- 不拆成“AI 工程榜 + 全站趋势榜”。
- 不用更大的关键词表替代语义审核，也不为填满栏目放行 `unknown`。
- 不修改 `.env`、运行时配置、已发送归档或真实外发状态。

## 4. 关键验收例

- 2026-07-12 历史候选池回放：GLM int4、LiteRT.js、LongCat 推理代码、Nemotron 吞吐优化至少有合格项进入“推理”；“奔三/迷茫/求助”不得从任何正式发布路径回流。
- Nvidia/CoreWeave 循环融资可进入行业/其他（若本身值得刊登），但不得进入“推理”。
- 同日既有合格推理又有其他 AI 进展时，两类都保留。
- Agent-Reach 能通过 AI 准入；IPTV 与仅通用语义 `agent` 的工具不能通过。
- 增星 661 的合格仓库不能因 AI 权重被增星 444 的仓库越过。

## 5. 被否决方案

“AI 工程榜 + 全站趋势榜”双轨方案被小孙否决：信息架构太乱，也偏离最初只想提高 AI 工程相关性和排序可信度的目标。该否决作为 F037 设计决策记录，不另立全局 ADR，因为影响范围仅限本 feature 的榜单呈现口径。

3. **是否更新全局指令：** 否；这是 F037 产品与架构合同，不是跨项目家规。
