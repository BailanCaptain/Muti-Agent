## Bug Report 六件套

1. **报告人**：小孙，2026-07-16 经典 Outlook 实收检查。
2. **Bug 现象**：点击每节尾“回目录”不能回到邮件顶部而停在/回到 GitHub 区；经典 Outlook 顶部刊头失真；“推理”等小标题下两张并排小卡之间出现淡灰色竖向矩形。
3. **复现步骤**：在 Windows 经典 Outlook 打开第二封 messageId=`<6604c27c-18fb-490f-3c85-c6cc87130058@qq.com>`；滚到“推理”等含两张并排小卡的小标题；观察两卡之间的 16px 中央间隔。第二封静态 HTML 中共有 9 个 `<td width="16" style="width:16px;font-size:0;line-height:0;">&nbsp;</td>`，与 9 组双栏卡一一对应。
4. **根因分析**：B035 的 Word 专用兼容引入了两个已修正问题：动态 VML 刊头接管多行高度，以及 VML 边界上的空顶部锚点。幽灵块的精确根因则是双栏中央 gutter 使用透明、带 `&nbsp;` 文本节点的全高单元格；Classic Outlook 把它当成一条贯穿整行的实体列渲染，而非纯几何间隔。
5. **修复方案**：保留已批准的字体、字号、颜色、陶土顶线和卡片结构；刊头改回自足的深墨 presentation table；可见眉题承载唯一 `name+id="DigestTop"`；GitHub 冗余 spacer 的间距附着到真实内容单元格；双栏 gutter 保留固定 16px 宽度，只删除 `&nbsp;` 并明确设置现有暖白 `C.paper` 背景。
6. **验证方式**：先取得针对中央 gutter 的 RED，再实现到 GREEN；重放 2026-07-16 原归档，断言 9/9 gutter 均安全，同时 Markdown、可见正文、外部 href 顺序、displayed/rest IDs、字节预算和归档/ledger hash 不变；生成本地 HTML/EML 供人工验收。本机 Office 损坏，最终 Outlook 点击与人眼效果必须由小孙确认，确认前不合入、不重发。

## 2026-07-17 V4.1：边框一致性回归

1. **报告人**：小孙通过两张 Outlook 方角模拟截图指出，同一正文区域出现有边框和无边框混用。
2. **Bug 现象**：栏目标题呈左边线 + 下边线，普通文章卡呈左边线 + 上下边线，焦点卡呈完整四边框；普通卡尤其像意外漏掉右边框。
3. **复现步骤**：打开 V4 Outlook 方角模拟，滚动至 AI 子栏目；检查 `Anthropic · 2 条` 标题及其下两张文章卡的四边 computed border。
4. **根因分析**：MSO 条件样式只把普通卡的右边框清零，没有先重置原内联四边框，因此上、下边框残留；栏目标题又单独保留下边框，形成 2/3/4 边三套语言，违反 `design-taste` 一致性锁。
5. **修复方案**：普通文章卡、榜单卡、其余速览卡和栏目标题全部先 `border:0!important`，再只恢复 3px 左侧规则；焦点卡作为唯一主推荐层级保留完整框。现代/手机端不改。
6. **验证方式**：新增 V4.1 RED→GREEN 合同；真实归档模拟中 21 张普通卡由 `1/0/1/3` 统一为 `0/0/0/3`，8 个栏目标题由 `0/0/1/3` 统一为 `0/0/0/3`；renderer `61/61`、组件 `903/903`、typecheck/build/lint 通过，现代端顶部和整页截图 SHA-256 与改前完全一致。全量测试仍有主工作区可复现的 9 个 Windows/bash 基线失败，与 renderer 无关。
